# Create PR

저장소의 실제 변경사항을 근거로 리뷰 가능한 PR을 만든다. 사용자가 본문 초안만 요청하면 초안 작성까지만 수행한다.

## 변경 범위 확인

- 적용되는 `AGENTS.md`, 저장소 PR 규칙과 템플릿을 확인한다. 사용자가 지정한 저장소, base/head 브랜치, 초안 여부를 우선한다.
- Git 상태, 원격 저장소, 현재 브랜치와 upstream을 확인한다. base는 사용자 지정 또는 확인된 저장소 기본 브랜치를 사용하고, 추측으로 `main`을 고정하지 않는다.
- base와 head의 merge-base를 기준으로 커밋 목록과 전체 diff를 읽는다. 작업 트리 변경은 PR에 포함되는 커밋과 구분한다. 요청 범위 밖의 파일을 수정하거나 자동 커밋하지 않는다.
- 동일한 base/head의 기존 PR을 먼저 확인한다. 이미 있으면 링크와 상태를 보고하고 중복 생성하지 않는다. 기존 PR 수정은 요청 범위에 있을 때만 수행한다.

## PR 언어 선택

- `ZOOSIXPARK/react-component-generator` 저장소는 PR 제목과 본문을 한국어로 작성한다. 다른 프로젝트는 영어로 작성한다. 기본적으로 두 언어를 병기하지 않는다.
- 프로젝트는 작업 폴더 이름이 아닌 대상 원격 저장소의 owner/repository로 식별한다. HTTPS/SSH URL이나 `.git` 접미사 차이와 다른 경로의 checkout/worktree는 같은 저장소로 취급한다.
- 사용자가 해당 PR의 언어를 명시적으로 지정하면 그 지정을 우선한다.

## 서브 에이전트가 제목과 본문 작성

PR 제목과 본문의 작성 주체는 서브 에이전트다. 메인 에이전트는 자료 수집, 검증, 결과 검토와 PR 게시를 담당한다. 본문 초안만 요청한 경우에도 작성을 위임한다.

- 서브 에이전트에게 선택한 언어, 대상 저장소와 base/head, 적용되는 저장소 규칙·필수 PR 양식, 커밋 목록과 전체 diff, 실제 검증 결과 및 알려진 한계를 제공한다.
- 서브 에이전트가 선택한 언어의 템플릿 파일만 읽고 제목과 본문을 반환하도록 요청한다. 한국어는 [references/pr-template.ko.md](references/pr-template.ko.md), 영어는 [references/pr-template.en.md](references/pr-template.en.md)를 사용한다. 저장소 필수 양식의 구조와 필드는 유지한다. 서브 에이전트에는 작성만 위임하며 push나 PR 게시를 맡기지 않는다.
- 메인 에이전트는 반환된 제목·본문의 언어, diff와의 일치, 검증 결과의 정확성을 확인한다. 수정이 필요하면 서브 에이전트에 돌려보내 완성하게 한다.
- 서브 에이전트 기능을 사용할 수 없다면 제약을 알리고 수집한 자료를 보존한다. 직접 작성으로 대체하려면 사용자의 지시를 받는다.

작성 시 다음 기준을 적용한다.

- 문제와 변경 후 동작을 먼저 설명한다. 최종 diff를 모르는 리뷰어가 목적과 영향을 이해할 수 있게 작성하고, 작업 과정이나 폐기한 접근은 필요한 경우에만 포함한다.
- 실제 실행한 검증과 결과만 기록한다. 미실행 또는 실패한 검증은 이유와 한계를 명시한다. 저장소 규칙에서 요구하는 검증을 수행하고, 실패를 성공으로 표현하지 않는다.
- 관련 이슈, 화면 자료, 호환성 영향은 확인된 내용만 넣는다. 이슈 자동 종료 키워드는 종료 의도가 확인된 경우에만 사용한다.

## PR 생성

- 사용 가능한 GitHub 연결 도구를 우선하고, 필요한 작업을 지원하지 않으면 인증된 `gh` CLI를 사용한다.
- PR 생성 요청은 지정된 변경사항에 대한 생성 권한으로 취급한다. 현재 head의 필요한 커밋을 push하는 작업은 대상 원격과 브랜치를 확인한 뒤 수행한다. 새 브랜치 전략, force push, 이력 재작성, 병합을 임의로 수행하지 않는다.
- 커밋되지 않은 변경사항이 요청한 PR에 필요하지만 커밋 권한이 없거나, 저장소·브랜치를 확정할 수 없으면 본문 초안까지 준비한 후 필요한 정보만 확인한다.
- CLI로 여러 줄 본문을 전달할 때는 UTF-8 임시 파일과 `gh pr create --body-file`을 사용한다. 저장소, base, head를 명시하고 사용자가 요청한 draft 여부를 반영한다.
- 생성 요청이 실패하거나 응답이 불명확하면 원격 PR 상태를 확인한 후 재시도한다. 인증·권한·브랜치 보호 문제는 반복 시도하지 말고 작성한 제목·본문과 함께 장애 원인을 알린다.
- 생성 후 PR의 URL, base/head와 게시된 제목·본문을 확인하고 PR 링크와 검증 상태를 간단히 보고한다.
